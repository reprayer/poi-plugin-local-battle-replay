# poi 本地战斗回放

一个给舰队 Collection 战斗响应使用的极简播放器：纯文字、直线动画、可切换明暗及自定义主题，不读取或打包原游戏图片、语音、音乐。它可以作为 poi 插件接收宿主已经截获的战斗响应，也可以直接双击打开独立页面并导入本地 JSON。

最重要的约束只有一条：**运行时不允许把任何数据发往任何服务器。**

## 目前实现

- 以“战斗开始”进入时间线；正常昼战依次播放索敌开始/结果、烟幕、可选喷式与基地航空、航空战与制空结果、支援、先制反潜、开幕雷击、阵形与交战形态、炮击、闭幕雷击、友军与夜战。
- 索敌开始和结果各显示 3500ms；确有飞机来源、机数、损失、触接、对空 CI 或伤害等直接响应数据的通常航空阶段，显示“开始”和“制空结果”各 3500ms。喷式强袭只保留“开始”提示，删除制空结果页，随后直接进入实际伤害箭头；基地航空队出击删除单独的“第 N 基地航空队攻击”提示页，直接显示该队制空结果。对空 CI 位于通常航空开始与制空结果之间；空航空对象不生成等待页面，航空伤害和其他攻击事件在此之外另计时间。
- 动态更新每艘船的 HP、损伤状态和击沉状态；加粗虚线箭头从攻击舰朝向目标的短边中点发出，抵达目标舰相向短边中点。普通与联合布局都把完整箭头置于卡片上方，联合舰队外侧舰船的攻击线可以跨过中间卡片，避免误认攻击来源。
- 健在、小破、中破、大破分别使用 `#389640`、`#E7BE58`、`#D67B1E`、`#BB4B2E` 显示状态、HP 数值和 HP 条；击沉保持原有黑灰与透明度样式。
- 我方 HP 右侧显示尚未消耗的应急修理要员/女神；发动后对应文字标识随事件快照消失。
- 读取航空战 `api_air_fire`，把我方对空 CI 的发动舰、类型和装备 master ID 显示为独立覆盖事件；详情格式为“舰名 · 类型 N · 装备 ID …”。
- 读取地图响应中的 `api_destruction_battle`，把最多三队基地航空队遭空袭时的 HP 损失、阵形、交战形态、制空状态和服务器损害代码合并成一个伤害事件。下方详情第一行显示双方阵形、交战形态和制空状态，第二行显示航空损失和基地损害。
- 地图响应或 poi 内存明确提供海域/节点时，在“战斗开始”页显示位置信息；纯数字紧凑海域号在最后一位前加入连字符，例如 `24 → 2-4`、`621 → 62-1`。活动难度直接读取 poi `info.maps[].api_eventmap.api_selected_rank`，显示为甲/乙/丙/丁；节点字母直接读取 poi 已有的 FCD 路线表，映射缺失时回退服务器数字编号，不自行猜测。
- 基地出击只使用响应直接提供的 `api_base_id` 标注“第 N 基地航空队”。每队只保留制空结果全屏页和实际伤害页，不再额外显示“攻击”全屏页。当前响应没有独立波次字段，因此不自行标注第一波/第二波。
- 在 poi 实时模式中读取已装备的应急修理要员/女神，并把发动与恢复 HP 显示为独立事件。
- 识别通常/联合舰队、敌联合舰队、夜战转昼战、特殊攻击、多目标攻击。
- 联合舰队的炮雷击阶段按响应类型排列：机动/运输对通常舰队为第一轮炮击→雷击→第二/三轮炮击，水打对通常舰队为第一/二/三轮炮击→雷击；对敌联合时，机动/运输为第一/二轮炮击→雷击→第三轮炮击，水打为第一/二/三轮炮击→雷击；单舰队对敌联合为第一轮炮击→雷击→第二/三轮炮击。每个 `api_hougeki*` 内部严格按服务器 `api_at_list` 顺序播放，0–5/6–11 分别映射主力/护卫；唯一额外修正是联合舰队夜战金刚级特殊攻击类型 104 的已知错误舰位。
- 航空战、开幕雷击和闭幕雷击把双方伤害合并在各自的单个伤害页中，按“我方攻击”“敌方攻击”分行显示全部目标和箭头；没有任何有效目标时不生成空伤害阶段。
- 普通舰队维持左右两列，卡片缩至原宽约三分之二并分别向窗口外侧对齐；存在任一方护卫舰队时切换为“我方主力｜我方护卫｜敌方护卫｜敌方主力”的四列六行布局，四组舰队显式固定在同一 CSS Grid 行，避免敌方护卫被自动排到敌方主力下方；内侧护卫舰队与中央线的距离约为旧布局的三倍。
- 当前事件信息按区域分工：左上使用固定高度的大字总览，只在战斗开始、基地航空队、航空战、先制对潜、开幕雷击、第一/二轮炮击、闭幕雷击、友军、夜战和战果报告时显示，其他事件留白；中央显示舰船、箭头及阶段/对空 CI/损管/战果覆盖页，并以对应英文概要取代通用 `PHASE`；覆盖页为胜负判定与 MVP 小字固定预留两行高度，写入完整文字后才显示，避免文字出现时推动标题；下方 104px 固定高度详情框集中显示攻击舰、攻击名称/类型、目标与伤害，内容过多时在框内滚动。
- 友军攻击期间，左侧仅显示友军舰队，不再把友军舰队堆叠在我方主力/护卫下方；前 7 艘纵向显示为友军一队，剩余最多 6 艘纵向显示为友军二队。显示拆列不改变服务器原始攻击索引，因此高亮、箭头和伤害仍对应原舰；友军阶段结束后恢复显示我方舰队。
- 中央舰船区域预留至少 400px 高度。攻击粗框和损管双线改为不参与盒模型尺寸计算的高亮，保留平移/双线效果但不会推挤相邻卡片；切换事件时会同步清除旧箭头并取消过期绘制回调，恢复自动播放时也不会重复重建当前帧；最近八条事件日志仍按实际条数逐渐增长。
- 战果响应直接显示胜负判定和普通/联合舰队 MVP；存在舰船或秋刀鱼等道具掉落时先停留 5000ms，再保持同一战果覆盖页并在下方详情框统一显示“获得舰船：xx · 获得道具：秋刀鱼（16）”。括号内为 poi 库存中的获得后总数；独立页导入无法取得库存时只显示道具名。最近事件日志的第一条战果记录保留胜负/MVP，第二条改为掉落内容，不再重复胜负判定。若下一场战斗先开始，新 battleId 会立即替换旧战果，不等待也不补播掉落提示。
- poi 明确提供退避舰位时，对应舰船卡片降低透明度并显示“退避”和 `HP —`，不显示击沉叉号，也不根据负 HP 自行猜测退避。
- poi 页面最小宽度保持 900px；纵向内外边距、卡片内边距、HP 间距和控制栏留白经过轻度压缩，舰船卡片之间仍保持 5px。
- 支持 poi 实时响应、`api_data`、`svdata=...`、数据包数组和 KC3Kai sortie replay JSON。
- 舰名优先使用 poi 内存中的舰船主数据；友军响应的 `api_ship_id` 会直接查询同一 master 表并读取 `api_ship_lv`。缺少友军主数据时舰名行只显示 `ID xxxx`，不再拼接“友军主力 N”。
- 战斗响应、舰队和回放时间线只保存在内存中。插件不写 localStorage、不读取剪贴板、不上传、不打开远程页面；粘贴内容只由用户在导入菜单中显式提交。唯一持久化内容是用户主动选择的主题模式、两个自定义颜色及其透明度百分比，保存到 poi 的 `config.cson`。
- poi 窗口右侧可在 LIGHT/DARK/CUSTOM 主题间切换；首次使用默认 LIGHT。LIGHT/DARK 以 `#3f3f3f` 与 `#fffaf0` 互换；CUSTOM 只允许通过两个颜色选择器指定背景和主文字色，并分别接受 0–100% 的受控透明度数值。背景透明度只作用于大面积页面底色；舰船卡片、按钮、详情框、CUSTOM 菜单等功能表面保持不透明，阶段覆盖页维持固定半透明，边框和攻击箭头保持不透明。HP 与损伤颜色不随主题改变。插件不提供任意 CSS 文本入口，因此主题值不能构造远程 `url()`。
- “本地战斗回放”大标题调整为 26–34px，使其明显高于左上 22px 阶段总括；英文小标题与中文标题的行框间隔为 5px，并继续按同一中心线对齐。左上总括区域保持固定高度，但删除下方浅色横线。大标题区本身也不使用分割线；实时/导入选项卡与 LIGHT/DARK/CUSTOM 控件位于同一控制行，该行使用较粗下分割线并与播放内容保留间距。两个主分页标签统一为至少 132px 宽、36px 高，比下方 34px 播放控件略高；三个主题按钮统一为 62px 宽、30px 高，使用与页面一致的非衬线字体、11px 字号和适度英文字距，继续作为次级设置。导入页的“读取粘贴内容”按钮固定在右列，与文件选择按钮对齐。

阶段顺序参考了 poi 的响应 action、`poi-plugin-prophet` 对宿主事件的订阅方式、KC3Kai 的 BattlePrediction，以及 `KC3Kai/kancolle-replay` 的事件队列。实现代码是重新编写的纯文字播放器，没有移植其图片、音频、分享或远程加载功能。实际查阅内容、源码位置和许可证入口集中记录在 [`REFERENCES.md`](REFERENCES.md)。

## 在 poi 中安装

要求 poi 10 或更新版本。该项目没有运行时 npm 依赖；React 和 React Redux由 poi 宿主提供。

正式版发布到 npm 后，在 poi 的“设置 → 插件”安装输入框中直接输入：

```text
poi-plugin-local-battle-replay
```

poi 会通过其内置 npm 安装器下载公开包，不需要把插件加入 poi 自带插件列表。

本地 tarball 安装方式：

1. 在本目录运行：

   ```bash
   npm test
   npm run audit:network
   npm pack
   ```

2. 在 poi 的“设置 → 插件”中选择本地生成的 `poi-plugin-local-battle-replay-1.0.0.tgz` 安装。
3. 启用“本地战斗回放”，再点击插件图标。插件使用 poi 的窗口模式打开独立视窗，默认进入“实时监控播放”。

维护者上传前检查与 npm 发布步骤见 [`RELEASE.md`](RELEASE.md)。发布动作不属于插件运行时，实际发布前需要由 npm 包名所有者登录并明确执行。

视窗中有两个互不覆盖的菜单：

- “实时监控播放”只消费 poi 已经截获的战斗与基地空袭响应，不显示导入框或等待响应的大块占位区。窗口已打开时，新战斗自动播放；昼战已经位于末尾并追加夜战时直接显示第一项新夜战事件，不再重绘昼战末帧。若原本暂停在昼战中途，则保留当前位置。
- “导入战斗数据”才显示本地文件与粘贴框。手动导入有独立播放器，不会覆盖实时战斗。

窗口关闭时，播放器 DOM、动画计时器和绘制逻辑都不存在，只有 poi Redux reducer 在内存中保留最近一场战斗数据。战果响应到达时会直接切到“战果报告”，不再先停留一轮旧战斗画面；若有舰船或道具掉落，5000ms 后再统一显示。等待期间若下一场战斗开始，会立即清除旧计时器并切换新战斗。战斗结束后再打开窗口时会直接停在完整结果，不会重新等待或从昼战开头自动播放。仍可按“回到开始”完整重播。窗口被系统隐藏时，自动播放会暂停，重新可见后再继续。

默认 1× 的事件时长如下：

| 事件 | 时长 |
| --- | ---: |
| 实际炮击、先制对潜伤害、开/闭幕雷击伤害及其他普通事件 | 2140ms |
| 先制对潜、开幕雷击、第一/第二轮炮击、闭幕雷击的全屏提示页 | 1800ms |
| 战斗开始 | 3200ms |
| 友军、夜战支援、夜战炮击阶段提示 | 3200ms |
| 阵形与交战形态 | 3000ms |
| 索敌开始、索敌结果 | 各 3500ms |
| 通常航空开始、制空结果 | 各 3500ms |
| 喷式强袭开始 | 3500ms（无制空结果页） |
| 每队基地航空队制空结果 | 3500ms（无单独攻击提示页） |
| 对空 CI | 3000ms |
| 应急修理要员/女神 | 3000ms |
| 战果报告至舰船/道具掉落揭示（有掉落时） | 5000ms |
| 时间线最后一帧、战斗结果 | 持续显示 |

0.5×、2×、4×会按所选倍数缩放这些间隔，且单帧最短为 120ms。暂停后再播放保持当前事件；即使已到末尾，“播放”也不会擅自回到开头，只有“回到开始”按钮会归零。

主题设置使用 poi 官方 `window.config` 接口，保存在现有配置节点下，不覆盖同节点中的窗口 `bounds`：

```cson
plugin:
  'poi-plugin-local-battle-replay':
    bounds:
      x: 41
      y: 69
      width: 898
      height: 912
    theme:
      mode: 'custom'
      custom:
        background: '#fffaf0'
        foreground: '#3f3f3f'
        backgroundOpacity: 100
        foregroundOpacity: 100
```

点击 LIGHT 或 DARK 时立即记住模式；CUSTOM 颜色与 0–100% 透明度先实时预览，点击“应用并保存”后才写入配置并统一提示“已保存自定义配色”。旧配置缺少透明度字段时自动按 100% 读取。输入和恢复默认预览分别明确显示尚未保存；仅点击 CUSTOM 不再显示含糊的保存提示。CUSTOM 面板保持 220px 宽，背景/文字标签使用 14px 字号，只有右侧 `58×30px` 色块能够打开原生色板，点击文字或行内空白不会误触；每行末尾的百分比字段用于透明度。状态提示位于按钮上方，为空时不占高度，因此按钮下方只保留与顶部相同的 12px 内边距。面板使用绝对定位，展开不会推移回放区域；原生色板打开时，第一次点击页面其他区域只关闭色板并保留浏览器实际返回的颜色草稿，CUSTOM 面板保持展开；色板关闭后再次点击菜单外才关闭整个面板。不同系统的原生色板对确认/取消的具体交互由 Electron/操作系统决定，插件只采用其触发 `input` 或 `change` 后返回的颜色。这里不注册键盘监听。若需要手工改变下次启动时的主题，可在 poi 关闭后把 `mode` 改为 `light`、`dark` 或 `custom`。插件只调用配置 API 写自己的 `theme` 子节点，不直接编辑 `config.cson`。底部控制栏中的速度和进度滑块向下微调至与播放按钮视觉平齐；帧计数全部使用普通字重 11px。

如果所用 poi 版本的安装界面不接受本地 tarball，也可把本项目目录链接到 poi 插件目录的 `node_modules/poi-plugin-local-battle-replay`，然后在 poi 开发者工具中执行：

```js
window.reloadPlugin('poi-plugin-local-battle-replay')
```

poi 的配置目录因操作系统和安装方式而异，因此这里不硬编码路径。

## 独立离线页面

直接双击打开 [`standalone/index.html`](standalone/index.html)。页面自带一份虚构 master ID 的本地样例；可以选择本地 JSON 文件，或粘贴 JSON 文本。独立页也提供 LIGHT/DARK/CUSTOM，但检测不到 poi 配置接口时只在当前页面内存中生效，关闭或刷新后恢复默认值。

独立页有两层网络锁：

1. CSP 使用 `connect-src 'none'`，并同时禁止表单提交、frame、object、worker、音频和远程字体。
2. 页面初始化时把 `fetch`、XHR、WebSocket、EventSource 和 `sendBeacon` 替换为拒绝实现。

不需要、也不建议用本地 HTTP 服务器启动它。

## 推荐数据格式

```json
{
  "version": 1,
  "battleId": "local-001",
  "location": { "mapId": "62-1", "difficulty": "甲", "node": 14, "spot": "N" },
  "roster": {
    "combinedType": 0,
    "playerMain": [
      { "name": "一号舰", "mstId": 1, "level": 80 }
    ],
    "playerEscort": [],
    "shipNames": { "901": "敌方旗舰" }
  },
  "packets": [
    {
      "path": "/kcsapi/api_req_sortie/battle",
      "body": { "api_f_nowhps": [], "api_e_nowhps": [] }
    }
  ],
  "result": { "api_win_rank": "A" }
}
```

`body` 也可以是带 `api_data` 的原始响应。完整紧凑样例见 [`examples/sample-battle.json`](examples/sample-battle.json)。

## 已知边界

- 原始战斗响应通常不含我方舰名；脱离 poi 导入时应在 `roster` 中补舰名，否则显示位置标签。
- 航空战和支援数据只提供汇总攻击来源时，播放器会显示“航空队/支援舰队”，不会猜测具体起飞舰。
- 对空 CI 的响应提供发动舰位、类型编号和装备 master ID，但不直接提供装备名称；当前界面保守显示服务器原始 ID，不从网络补资料。
- 基地空袭来自地图 `start/next` 响应中的 `api_destruction_battle`，不是普通战斗接口。播放器把各基地 HP 扣减、阵形/交战形态、制空状态及 `api_lost_kind` 原始代码合并为一个伤害页；随后到达的正常战斗会替换这段短回放。
- 普通战斗响应本身通常没有海域或节点。实时模式暂存地图响应的 `api_no` 以及 poi 已有的 `sortieMapId/currentNode`；活动难度来自 poi 已缓存的 `info.maps`，字母点来自 poi 已加载的 `fcd.map[海域].route[api_no]`。任一字段缺失时只省略对应文字或回退数字节点，不读取请求参数、不联网补表，也不猜测字母点。紧凑纯数字 `sortieMapId` 只做最后一位前插入连字符的显示格式化，不改变原始响应。
- 演习战斗明确不继承出击地点，`location` 固定为空，因此不会显示演习海域编号，也不会误显示上一场出击的位置。
- `api_air_base_attack` 条目直接提供 `api_base_id`，但当前已核对样例没有独立波次字段。播放器显示基地队次，不根据数组顺序猜测波次。
- poi 实时模式会从出击舰队装备实例中识别 master ID `42`（应急修理要员）和 `43`（应急修理女神）。要员按最大 HP 的 20% 向下取整且至少恢复 1 HP，女神恢复满 HP；一件装备在本地时间线中只发动一次。演习中不触发。
- 退避状态来自 poi `store.sortie.escapedPos` 的明确舰位；联合舰队按主力与护卫拼接后的零基舰位读取。缺少该状态的手动数据不会仅凭 `HP = -1` 推定退避，可在 roster 舰船上显式提供 `"retreated": true`。
- 手动导入的数据若希望重现损管，需要在对应 `roster.playerMain/playerEscort` 舰船中提供 `"damageControls": [42]` 或 `[43]`；缺少装备信息时只能等待后续服务器 HP 快照校正。
- “紧急修理资材”属于战斗外的泊地修理资源，不是战斗攻击事件，本播放器不为它生成阶段。
- 新活动加入全新 API 字段时，播放器会保留已知阶段并忽略未知字段；应补匿名化样例和测试后再扩展。

## 字体

项目没有打包字体文件，也不会联网下载字体。界面只按顺序引用本机已安装的 `Noto Sans CJK SC`、微软雅黑、Hiragino Sans GB、系统无衬线字体，以及 `SFMono-Regular`、Consolas、系统等宽字体作为回退。

这种 CSS 字体引用不会把字体随插件再分发。若以后希望把 Noto 字体文件直接放进插件，应附带其 SIL Open Font License；微软雅黑、Hiragino 和 Consolas 属于专有字体，不应未经相应授权直接打包。

安全模型与禁止事项详见 [`SECURITY.md`](SECURITY.md)。
